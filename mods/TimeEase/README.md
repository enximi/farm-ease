# 适时而归 · TimeEase 0.1.6

**0.1.6 已通过 Mac 单人保存后休息流程的人工验证，用户确认现有手柄交互可用。同版远程联机和纯本地分屏协调退出仍属未实测预览；混合远程与分屏仅提醒。Windows 使用同一版本源码针对当地游戏目录构建，启动后确认保存观察器是否支持。**

每天 60 分钟现实游玩额度，北京时间（Asia/Shanghai）00:00 重置。独立 SMAPI Mod，可单装；在「农场随心」显示今日进度，也可执行 `timeease status`。

## 计时与保存

- 从存档载入完成开始计时，跨存档和游戏重启累计。同一系统用户的不同游戏安装共用额度。
- 菜单、对话、暂停、过场、保存过程及后台切换都计入现实会话时间；标题和休息界面不计时。分屏只由主屏记录一次。两个独立游戏进程各自的会话时间相加。
- 使用单调时钟计算经过时长，系统时间仅用于分配自然日；跨零点的时间拆分到两天。电脑休眠期间的计时取决于系统单调时钟，未实机验证。不修改系统时钟或限制其他应用。
- 剩余 10 分钟提醒；额度耗尽提醒。单人仍可结束当前游戏日。只读观察已核对的原版内层保存状态机，确认其完成正式文件替换，再结合 SMAPI `Saved` 生命周期通知；等原生保存、出货结算、过夜同步和菜单队列结束后，才显示休息界面。仅有 `Saved` 或 `DayStarted` 不构成成功证据；不替换仍在进行的保存/结算菜单。原生单人菜单暂停世界。
- 休息界面可主动返回标题（鼠标、A/B、回车/Esc）；不会自动睡觉、退出游戏进程、调用存档写入或丢弃当天进度。新现实日额度可用时自动恢复。
- 当日满额后重新载入已有存档，只有确认它来自磁盘解析并到达正常、无其他流程的载入边界才拦截，不再赠送一个游戏日。新建角色不冒充磁盘存档，需取得初次保存的实际完成证据。原版已在保存前生成新一天，因此限制的是继续操作，而不是阻止隔夜计算。
- **远程联机预览需房主及所有参与者安装并启用同版本 TimeEase，每台电脑一名玩家。** 房主取得实际保存完成证据后短暂持有原生暂停，保留各方结算菜单并等待全员报告就绪。房主满额时自动返回标题、结束整个房间；仅客机满额时只向相应客机授予退出许可，等待其离开后恢复世界。合作模式只有房主一人也走保存后的主机退出路径。无法确认时取消操作，正常保存后手动休息。**纯本地分屏走下述本地协调；混合远程与分屏仍只提醒。**

## 无法确认安全时的处理

0.1.6 修复人工测试中发现的保存观察漏判：0.1.5 启动检查通过，但原生保存完成后 `observed=False`。现在直接只读观察已核对的内层 `MoveNext`，在 SMAPI 保存开始事件创建单次令牌，后台回调只原子记录状态机身份与完成标志，不读写游戏状态。状态机未观察、提前结束、异常或多个状态机混入都不能放行；新增 `native_steps` 用于人工验证。不能仅凭旧日志确定工厂调用被 JIT 内联，这只是已排除的脆弱观察路径。

保存观察器目前只支持经过本机源码核对的 Stardew Valley 1.6.15 build 24354 内层保存实现，启动时比对状态机 IL 指纹，并检查其 Harmony 补丁冲突。不同实现、其他 Mod 改写保存或观察器未能安装时，明确退回提醒模式，不建立强制退出权限。

原生保存枚举器提前结束、抛异常、取消、禁用保存或错误画面均不能产生放行凭证；本 Mod 原样传递枚举进度与异常，不调用保存、不恢复或改写游戏存档。凭证只属于当次会话的存档与游戏日，不能复用旧凭证或跨农场复用。

若在保存/载入边界出现剧情、其他菜单、排队菜单、传送或未知流程，会说明本次不能安全拦截，保留原生流程。进入休息后若出现新保存/错误/外部菜单，也会撤销本 Mod 的退出权限并保留该流程；点击返回标题时再次检查边界。**不能稳健确认的情况仅提醒，不能承诺严格阻止继续玩。** 不会为了限时清理菜单、跳过过场或强退。

`RoomConsensus` 负责精确成员集合与一次性凭证，`SessionNetwork` 接入远程运行时。联机尚未实机验证。实现条件见源码 `COORDINATION.md`；纯本地分屏逐屏收集就绪并由主屏统一退出，不创建多屏休息 UI。

## 如何调整与加时

- 游戏标题主界面：右上角「适时而归设置 · F11」，或按 F11。
- 游戏内：农场随心 →「适时而归」，自由操作时也可按 F11；控制台 `timeease settings`。
- 休息界面：直接点「设置」（手柄 X / F11）或「今日加时」（手柄 Y / F12），不需要先加时才能改每日限额。
- 每日限额、重置时刻和提醒提前量可用左右键、手柄方向键或鼠标 −/+ 调整；键盘数字可直接输入。重置时刻输入四位 HHmm。
- 「保存每日设置」持久保存默认额度，当前额度立即按新每日限额 + 今日加时重算，绝不清零已用时长。已用 65 分钟时将每日 60 改为 90，真实剩余 25 分钟；降低至已超额只进入提醒/下一次安全保存后的限制，不打断进行中的游戏日。
- 「仅今天加 15 分钟」「仅今天加 30 分钟」「自定义今日加时」都会先显示确认页，列出今天的新总额度及真实剩余；确认后才写入独立累计记录。反复重试同一次请求不会重复加时。次日仍按默认额度，今日加时不会变成长期默认。
- 已满额时标题也保留这些入口；保存后按新总额重新判断能否开始。若加时后仍低于已用量，继续限制。
- 休息界面及其设置子页都不计时。提高额度后关闭设置才恢复游戏；取消/关闭按实际额度返回休息或恢复。普通游玩期间打开设置仍按既有会话规则计时。
- 新重置时刻在正常返回标题后生效，避免进行中的会话突然换计费日；每日分钟数和提醒提前量立即更新。时区仍可通过 config 配置。
- 正在保存、结算、对话或加载/连接时，设置入口会拒绝替换原生流程。未保存的设置在返回时放弃；今日加时的确认不会替代「保存每日设置」。

## 配置

首次启动读取/生成 SMAPI 标准 `Mods/TimeEase/config.json`：

```json
{
  "Enabled": true,
  "DailyLimitMinutes": 60,
  "TimeZoneId": "Asia/Shanghai",
  "ResetTime": "00:00",
  "WarningMinutes": 10
}
```

额度为 1–1440 分钟；提醒分钟数为 0（不提前提醒）到额度减一。时区使用系统支持的 IANA ID，重置时刻为 24 小时 `HH:mm`。其他时区遇到夏令时跳时，在首个有效分钟重置；重复时刻只在首次出现时重置。自然日键使用 `yyyy-MM-dd`，更改时区/重置时刻会改变日期归属，建议保留确认的时区。

在正常保存并返回标题后，执行 `timeease reload` 或菜单系列的刷新配置；进行中的会话拒绝配置热切换。无效配置会报错并阻止单人下一次游玩，修正后在标题重新读取。记录故障时保留当前游戏日正常保存的机会。

## 记录与容错

记录位于 `.NET Environment.SpecialFolder.ApplicationData/StardewValley/TimeEase/usage.json`，启动日志输出完整路径；macOS 通常位于 `~/.config/StardewValley/TimeEase/`。独立于游戏 `Saves` 和 `Mods`，本 Mod 不读取或修改实际游戏存档文件。

记录按会话保留绝对累计数，进程间用独占文件锁串行读改写；临时文件落盘后原子替换，并保留 `usage.json.bak`。重试绝对累计值不会重复记账，也不会用旧进程缓存覆盖其他会话。每约 2.5–3 秒保存一次并预留未来 5 秒，返回标题退回未用预留；意外关闭可能多计至多约 5 秒，避免通过反复短时重启清零。游戏更新循环长时间停止、磁盘故障或强制断电仍可能影响最后一段记录，不承诺防篡改或断电事务保障。

记录损坏或有备份但主记录丢失时不会默默重建为空；日志报错，进行中的单人游戏可先保存，再在休息界面等待修复。锁竞争和暂时写入失败会重试。备份不自动回滚，避免较旧备份恢复更多可用时间。不要删除计时文件来排障；关闭游戏后先另存副本。

这是个人时间管理工具。停用 Mod、编辑配置/记录、修改系统时间或使用其他 Mod 可绕过限制；不包含侵入性的系统级防绕过机制。

## Mac 最短人工验证（预览包）

请通过 SMAPI 手动启动，只用一个新建的单人测试农场，先不要用正式农场或合作模式。我们不会自动启动或操作游戏。

1. 标题右上「适时而归设置 · F11」（Mac 功能键被系统占用时可试 Fn+F11，或直接鼠标点击）。每日限额改为 **2**、提醒提前量 **1**，保存每日设置；北京 00:00 不变。若今天已用超过 0 分钟，将限额设为“已用分钟向上取整 + 2”，避免无法新建测试农场。初次安装仍默认 60/10，不会自动改成测试值。
2. 新建单人测试农场，等待现实约 2 分钟，确认剩余提醒与满额提醒；菜单、暂停和后台均计时。满额后应仍能操作，手动上床结束当天。等原生保存和结算完成，应出现休息界面。可把一件物品放入出货箱，再睡觉，覆盖出货结算流程。
3. 休息界面选「返回标题」，正常关闭并重新启动 SMAPI；额度应保留且标题仍有设置入口。关闭前可在 SMAPI 控制台输入 `timeease diagnose`。若没有拦截，不要强行关进程；正常完成原生保存，再提供日志。
4. 标题设置先试“今日 +15”：确认页应显示新总额和真实剩余；取消一次应不加时，再确认一次。进入测试农场检查额度恢复；可用相同步骤检查 +30/自定义。**今日加时会保留至北京时间午夜，重启不会撤销；本步骤会增加今天的实际可用额度。**
5. 最后在每日设置恢复 **60 分钟、提醒 10 分钟、重置 00:00**，点击保存。检查提高额度没有清空已用时间；测试分钟仍计入今天。今日加时与每日默认分开，不因恢复默认而删除。只需验证核心路径时可跳过第 4 步。

`timeease diagnose` 输出当前计时、模式、保存检查支持状态及边界。通常提供本次 SMAPI 日志即可，无需截图；仅文字重叠、按钮无法点击等界面问题需要截图。Mac 默认日志：`~/.config/StardewValley/ErrorLogs/SMAPI-latest.txt`（如设置了自定义配置目录，以 SMAPI 启动日志为准）。退出后、下次启动前另存一份，避免最新日志被替换。

日志标记均为 `[TimeEase] event=...`：`observer_ready supported=True` → `session_loaded` → `quota_reached` → `save_begin` → `save_evidence committed=True` → `settlement_complete decision=Rest` → `block_enter reason=quota`。没有证据或安全边界时看 `block_refused` / `boundary_released`，不要把它当成已经成功限制。`settings_saved`、`bonus_added` 和 `snapshot` 用于核对额度变化。没有 `observer_ready supported=True` 时，仅能验证计时、设置和提醒。加载已保存农场也可产生安全边界，因此相关日志不一定含有新的保存事件。

## 远程联机人工验证（0.1.3 接入，0.1.4 保留）

先完成上述单人测试，再与知情参与者用新测试农场验证。**房主和所有客机必须同时安装并启用 0.1.6；每台电脑一名玩家，不使用分屏。** 此预览尚不满足 Windows 正式部署条件；只有 Mac 一台设备时先测“合作模式仅房主”，不能因此宣称远程验证通过。

- 房主满额：房主设置为“今天已用向上取整 + 2”分钟、提醒 1；客机保留较高额度。一起进入测试农场、等待房主满额，再全员手动睡觉并确认各自出货/升级菜单。保存与全员结算完成后，房主应回到标题，客机因房间结束离开；确认重载测试农场是已保存的新一天。
- 仅客机满额：房主提高额度、客机设短限额，手动睡觉保存。全员完成结算后应仅满额客机离开，房主房间继续；没有达限额的客机应留下。
- 双方均未满额：正常睡觉，完成同步后短暂停顿应解除，不应有人退出。缺少同版 Mod 时只提醒；禁用的同版 Mod 不会响应，等待最多 120 秒后取消暂停与自动退出，不强踢。参与者加入/意外离开、界面或额度日期变化、超时均撤销本轮权限。主机主动按原生恢复键会取消本轮，不能借此强制绕过保存。
- 用户可以慢一点确认某人的结算菜单：其他人应等待，不能在那个人尚未完成时退出。若超时/原生异常，正常完成保存并手动返回标题，提供双方日志，不强制关闭游戏。

双方分别在 SMAPI 控制台输入 `timeease diagnose`，正常退出后保留双方 `SMAPI-latest.txt`（最新日志下次启动会覆盖）。房主关键链：`save_evidence committed=True` → `room_checkpoint` → `room_pause` → 全部 `room_ready` → `room_decision action=EndRoom/ExitClients/Resume`；客机应有 `room_checkpoint_received`、`room_settlement phase=Ready`、`room_ready`。实际执行记录为 `room_exit role=host/client`。`room_cancel reason=...` 表示取消本轮，不能当作成功限制。

120 秒等待上限是失败保护，不是退出依据。房主原本已暂停时不会取得暂停或退出权限；仅释放自己取得的暂停，不替换保存/结算菜单，不调用存档写入。停止和恢复游戏进程均由用户操作。最后各自恢复 60/10/00:00，今日已用和加时保留。

## 纯本地分屏人工验证（0.1.4 新增）

只用 Mac 上新的合作测试农场与知情参与者，开启本地分屏，不接入远程玩家。整台电脑共用每日额度，只计一次现实时间。

1. 主屏 F11 或「农场随心→适时而归」设置短限额（已用分钟向上取整 + 2）、提醒 1 分钟，保存；副屏的设置入口只提示在主屏调整，不替换副屏菜单。
2. 等满额提醒后，各自手动睡觉、完成原生出货/升级等菜单。主屏成功保存后会暂停世界；各屏仍应能完成原生结算，慢的一屏不会被跳过。
3. 每屏全部完成结算并收到主机暂停后，主屏自动返回标题，原生主机清理移除所有副屏。不是由副屏退出自身，也不是在保存事件内立刻退出。不会显示单人休息菜单。
4. 标题右上设置/F11 仍可修改每日额度或确认今日加时；提高后能重新进入，累计已用不清零。最后恢复 60/10/00:00。未满额时正常结算后继续，不能误退。

日志链：`save_evidence committed=True` → `local_checkpoint screens=...` → `local_pause owned=True` → `local_ready ready=全部/全部` → `local_exit role=host all_ready=True`。`local_cancel` 表示本轮取消。成员变化、远程加入、日期变化、异常菜单、120 秒超时、主机暂停已被别人持有/解除均取消自动退出，不清理原生流程。主屏可在普通游玩或统一回标题后打开设置与今日加时；保存结算期间入口照旧拒绝。

纯本地分屏及远程联机均未经实机验证；若只有一个玩家/控制器，未执行多屏测试就不能标为通过。本版不支持远程与本地分屏混用的统一限制。

## 全程手柄操作（0.1.5 已由用户确认，0.1.6 保留）

标题主界面按 **L3（按下左摇杆）** 打开设置，屏幕右上也标有 L3/F11。已满额的标题休息页可按 A 进入设置，X 直接设置、Y 今日加时。游戏内沿用「农场随心」入口：短按原来的菜单键（默认 L3），↑↓选「适时而归」后 A；也可按原版 Menu/Start 打开游戏菜单，LT/RT 切到「农场随心」再选。不会在自由操作时占用 A/B/X/Y 工具动作。

设置页：↑↓或左摇杆选项，←→每次增减 **1 分钟**，按住会连续调整；LB/RB 快调（每日/自定义 10 分钟、提醒 5 分钟、重置 15 分钟）。重置可逐分钟到任意 HH:mm。A 选择当前项；调完每日/提醒/重置后移到「保存每日设置」按 A。B 返回放弃未保存设置，Menu/Start/Back 在本 Mod 页也返回。今日 +15/+30/自定义先按 A 进入确认页，↑↓选择确认/取消，A 执行所选，B 只取消确认；成功/取消后恢复原焦点。自定义可完全用手柄逐分钟调整，不需要键盘输入。

休息页：↑↓选三个按钮、A 执行；X 设置、Y 今日加时；游戏内休息页 B 安全返回标题，标题休息页 B 保持标题。按钮竖排，窄窗口自动滚动设置选项；原版 snappy 可点击组件、当前焦点与绿色框跟随选中，窗口改变时重算。不需要更改原版手柄/snappy 设置；抑制已处理的按钮，防止一按 A 进入确认页同时又确认加时。

分屏共享设置仍只由 **主屏的控制器** 操作，副屏不能移动主屏焦点或改共享限额；副屏原生操作照常。统一回标题后主屏 L3 可改额度、加时再进入。

最短手柄验收：标题 L3 → 把限额/提醒调整到短测试值 → A 保存 → B 返回；游戏内从农场随心再次进入 → 自定义加时调到 7 分钟 → A 预览、B 取消，检查额度未变；再打开 +15 预览检查确认/取消导航（确认会真实增加今日额度）。额度用完、手动保存后，在休息页验证 X 设置/Y 加时和 B 返回。最后手柄恢复 60/10/00:00 并 A 保存。

日志 `settings_open` 与 `controller_action menu=... button=... focus=... screen=...` 可辅助判断按钮是否到达正确页面；方向连按不会刷操作日志。实际控制器识别、按键映射、长按节奏、原版 snappy 开/关、窄屏及分屏焦点仍需用户人工测试，不把源码/编译称作体验通过。
