# 随取随用 / Storage Ease 1.5.0

独立仓储便利 Mod，目标 Stardew Valley 1.6.15 + SMAPI 4.5.2，接入「农场随心」统一菜单。默认随行模式：所有玩家在各地访问所有支持的箱子，原版制作页自动取材。不会扩大背包，不会自动存入采集物。

## 使用

1. 短按 L3 松开或按 F7 打开「农场随心」，选择「随取随用」直接打开上次使用的箱子；不再经过功能页和“打开仓储”。**长按 L3 约 0.5 秒 / 按 F9** 可从游戏直接开箱，长按触发后松开不会再弹菜单。L3 跟随共享配置中的 MenuButton；未安装本 Mod 或关闭长按开箱时，菜单键仍在按下时打开普通菜单。
2. 上次箱子按玩家记录 ID，随存档保存，搬动箱子后仍能找到；只记录标识，不复制库存。首次使用、箱子已拆除或关闭远程时显示箱子列表。多人可同时打开同一个箱子；只有实际操作才会等待使用锁。
3. 原版箱子界面上方有「全部箱子」，鼠标点击或按 **L3 / F7** 进入列表。每行显示第一个物品的图标、名称和箱子位置，搜索框按物品或地点过滤；F 聚焦搜索，手柄 Y 打开文字输入。上下选箱，左右选择底部操作，Enter / A 执行；滚轮、PageUp/PageDown、LB/RB 翻页。
4. 箱子自动以第一个非空物品识别，不需要手动命名。所有玩家都可切换箱子的“远程开关”“取材开关”。列表右上角「设置」（Menu / Start 或 F6）调整随行/舒适模式、制作/烹饪自动取材与长按开箱开关。列表约 5 秒刷新，也可手动刷新。
5. 退出箱子或列表：快捷键/手动开箱路径直接回到游戏；从统一菜单进入则返回「农场随心」首页。等待开箱时可按 B / Esc 取消；查看全部箱子前要先放下手中的物品。

快捷键只在角色可自由操作时触发，不接管其他菜单或文字输入。长按状态按分屏区分，失焦、换地图、返回标题、过夜或刷新菜单配置时清除。F9 可在 `config.json` 的 `KeyboardOpenButton` 改键或设为 `None` 禁用；`EnableMenuHold` 控制长按开箱，`MenuHoldMilliseconds` 默认 500，允许 250–2000 毫秒。

## 箱子标签切换

走到箱子旁手动打开，或从仓储列表打开箱子后，原版箱子界面上方显示一排「首件物品图标 + 序号」的紧凑标签和「全部箱子」入口。常规标签宽 64 像素，箱子少时也不拉宽，按可用宽度显示尽可能多的标签。当前箱子高亮；箱子较多时随切换自动滚动。

- **手柄 LT / RT**：上一箱 / 下一箱，与统一菜单切换标签的按键一致；首尾循环。
- **键盘 PageUp / PageDown**：上一箱 / 下一箱；上下左右仍用来选择物品。
- **鼠标**：点击物品图标或两侧箭头；悬停显示完整物品名称、地点、坐标、序号和总箱数。
- 标签使用原版箱子顶部空白区域，不移动箱子与背包格子；LB / RB 仍执行原版箱子中的导航操作。
- 其他标签包含全部开启远程访问的箱子，沿用随行/舒适模式限制。手动打开的关闭远程访问的箱子仍能正常操作，但切到其他箱子后不能从标签远程返回。
- 鼠标手中有物品时先放下才能切换。取放操作等待期间不重复提交、不切换箱子；仍可按 Esc / B 关闭并取消未执行的操作。
- 标签切换只切换浏览对象，不长期占用箱子锁；目标移走或关闭远程访问时停留原箱子并提示。祝尼魔箱子的不同入口继续使用同一份原生库存，操作时也共用一把锁。

标签和列表读取箱内按格子顺序排列的第一个非空、数量大于零的物品。取走首件、放入物品或整理箱子后，图标与名称随当前库存更新；不会为了识别箱子而移动、排序或复制物品。空箱显示淡色箱子图标和“空箱子”名称。多个箱子首件相同，可按序号和位置区分；箱子列表顺序仍按地点和坐标排列，不随物品名称跳动。

移除手动改名入口；旧的自定义名字不再参与显示或搜索，不修改存档中的旧名字字段。搜索仍会匹配箱内全部物品，不只匹配首件。远端地图尚未同步时暂用房主目录里的预览，收到原生库存后使用本地物品名称与图标。

## 默认与范围

- **随行模式（默认）**：在正常可操作的地图使用；活动、过场、昏迷等状态不可用。
- **舒适模式**：仅当玩家在农场室外或农舍/小屋时使用。限制玩家所在地点，材料箱仍可位于其他已登记的固定地图。
- **制作自动取材（默认开）**：使用普通制作页或原版工作台，先扣背包，再用工作台已有材料，最后使用允许取材的箱子。
- **烹饪自动取材（默认关）**：开启后扩展原版厨房/野炊工具的食材来源及可用调味料；不添加随地烹饪入口。不改变原版冰箱取材规则。

普通木箱、石箱、巨型箱子和祝尼魔箱子统一供所有玩家使用，默认“远程开、取材开”。不按放置者或箱主筛选列表、标签、取放、制作材料和设置操作。所有玩家都可调整远程/取材开关，开关对全体玩家一致生效；箱子有待执行或正在执行的取放/制作操作时暂不允许更改设置；单纯打开界面不阻止修改。祝尼魔箱子仍使用原有库存，多个入口不会重复计算材料。

从旧版升级时，旧的 shared 标记不再读取，也不再写入；此前设置为私人的箱子自动向所有玩家开放，无需重新放置或逐箱修改。不改写原版箱主字段或库存。远程和取材开关保留此前的选择，关闭时对所有玩家一视同仁。

不包含 NPC/奖励箱、开局礼物、冰箱、迷你出货箱、机器附件库存、自动装料箱及第三方自定义 Chest 子类。原版冰箱仍通过厨房正常使用。箱子位置覆盖固定地图及建筑内部，不纳入临时生成的矿洞/火山楼层。列表汇总所有支持的箱子；所有开启取材的箱内材料均可供玩家制作使用。

## 制作与游戏性

只扩展原版 CraftingPage，不改写玩家背包，也不会将远程物品用于自动送礼、交任务、献祭、出售或机器投料。配方学习条件、产量、品质、成就与制作统计沿用原版。

箱内材料显示在原版配方可制作判定与提示中。实际制作前先取得本次需要箱子的原生 NetMutex，再检查当前配方、材料、取材开关与背包容量，调用原版消耗逻辑，成品放入背包。没有空位或可合并位置时拒绝制作，即使这次消耗材料可能腾出位置，也需先手动腾出空间。

等待锁期间重复同一配方的点击会合并为最多 25 次，取得锁后逐次检查材料与空间；只使用本次已锁定的材料箱，不足即停止，可再次点击继续。不同配方需等前一次完成。其他玩家正在查看或操作的箱子仍参与材料预览；实际制作排队取得所需箱子的锁后重新检查材料。不会为了浏览制作页长期锁住所有箱子。

## 多人

房主和使用本功能的玩家需安装相同版本 StorageEase 1.5.0。不使用本功能的玩家不必安装。分屏配置与当前操作按屏幕区分；同机配置文件作为下次启动的共同默认。

支持多位玩家同时打开同一箱子，包括走近手动打开、快捷开箱与标签切换。界面显示原箱子的联网库存，其他人的取放通过游戏网络同步到当前界面。打开界面本身不占锁。

- 左键整叠、右键拆分、存入、整理、补齐堆叠与自动制作均需协调。房主将冲突请求排队，并一次性预留本次需要的全部箱子；随后由发起操作的客户端取得原生 NetMutex，调用原版取放/制作逻辑，再释放。本版采用“房主协调、原生锁内执行”，不是房主直接改写远端玩家背包。
- 同一箱子中的实际修改依次执行。操作前复核箱子实例、位置、开关、菜单、背包和光标；等待时没有提前扣物品或发放物品。不同箱子的操作无需共用一把全局锁。
- 点击的那一叠仍在原格时按最新剩余数量操作；被拿空、替换或整理移位时取消旧点击，提示重新选择，不会自动拿新占据该格的物品。整理和补齐堆叠在取得锁后使用最新库存。背包容量与手持剩余物品沿用原版处理。
- 一名玩家同一时间只提交一个取放操作；排队时重复点击不累计执行。制作同配方仍可合并最多 25 次。排队超过约 15 秒、换地图、菜单关闭、分辨率变化或保存时取消未执行操作；鼠标光标上已经实际取出的物品仍由原版退出清理归还背包，放不下则按原版掉落。
- 先发送背包与箱子库存增量，再发布解锁；取得锁后等待原生网络插值完成，房主也等待解锁后的同步缓冲才放行下一个操作。取消后迟到的原生锁回调会释放自己取得的锁；不会按超时强行解开仍在操作的玩家的锁。断线回收沿用原生机制。

房主发布目录与原版地图网络字段订阅，初始状态及远程增量沿用既有同步通道。物品始终存放在原箱子/原玩家背包，不引入物品克隆仓库或新的存档布局。箱子元数据为 ID 与远程/取材开关；玩家元数据保存上次箱子的 ID。

与田园巧整共用原生箱子锁：实际取放/制作期间不能搬移该箱；仅浏览期间可以搬移，旧界面检测到位置变化后关闭，重新打开即可。原版工作台或未安装新版 Mod 的玩家可能仍长期持有原生锁，其他操作会等待或超时，不会绕过该锁。第三方自定义菜单/库存操作不在本版协调范围内。

## 配置与安装

`Mods/StorageEase/config.json`：`Anywhere=true`、`CraftFromStorage=true`、`CookFromStorage=false`。在箱子列表的设置页切换后自动保存；统一菜单的 F6 可重读配置。`storageease` 直接打开上次的箱子。

多人同箱功能需房主和参与者统一更新至 1.5.0；其他系列 Mod 本次无需更新。

独立安装即可提供统一入口；与其他系列 Mod 同装时自动汇总，不需要额外核心 Mod。退出游戏后移走 StorageEase 即可停用，原箱子物品照常可用，已保存的少量箱子元数据不会影响原版取放。

本次仅进行源码核对、Release 编译与安装校验，按要求未启动游戏、未编写测试。图标布局、不同缩放/分屏、多人同步更新及此前多人同箱功能仍需实机确认；编译成功不等于已完成实机验证。
